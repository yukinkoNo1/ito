- 本文の上限 32KB は全ルートに効く（Content-Length があってもなくても。GET に本文はない。圧縮した本文は展開しない）。readBodyFirst も同じ上限の中で読む

## 観点ごとに確かめたこと（問題なし）

- **本人確認**: 127.0.0.1（::1）以外で待ち受けない（env.test.ts）。ts はカーネルモード（compose.yaml の `TS_USERSPACE: "false"`）で app は `network_mode: service:ts`。本番では X-Dev-Login を無視し、dev モードは NODE_ENV=development のときだけ（middleware.test.ts・env.test.ts）。/healthz の Host の例外はパスがちょうど `/healthz` のときだけ（middleware.test.ts「Host 検査・/healthz」）。フィード以外の /api は ID ヘッダがなければ 401 で、連携キーを付けても同じ（audit-routes.test.ts）
- **CSRF**: 状態を変えるすべてのルートが、X-Ito-Client・Content-Type・Origin・Sec-Fetch-Site のどれが欠けても 403 csrf（audit-routes.test.ts でルートの一覧から機械的に、6 通りの壊し方）。GET もフィード以外は X-Ito-Client と same-origin が要る（A3）
- **非公開**: 同期・履歴・ゴミ箱・409 の本文・通知の文・まとめ・書き出し（JSON・ICS）・検索・空き時間・一言入力の重なり・表示用フィードは projectEvent・canSeeContent を通る（security-map の T5 の行のテスト）。見つけた穴は A7〜A9
